Resolve any Java type name to its fully qualified name and absolute "path" — the first step whenever you need a class, interface, enum, record, or annotation you cannot already address by path.

Call this FIRST, before find_file, search_project, or guessing a path from a package name: if you have a simple name, import, FQN fragment, or stack-trace type — NPE, ProcessManager, com.foo.Bar — call find_java_type on it instead of grepping contents or constructing src/com/foo/Bar.java by hand. Do NOT use search_project to find a type declaration (it scans contents and is far slower). Do NOT use find_file when you need the FQN or declaration — find_file matches filenames, this resolves types. For non-Java files (PHP, JS, configs, docs) use find_file instead.

A plain query matches camel-case initials by default (kind=camel): NPE finds NullPointerException. Use kind=prefix for ChatPanel*, kind=exact for a whole simple name, kind=regexp for case-insensitive patterns. At least 2-3 characters; short prefixes return many hits.

It answers instantly from the Java class index across open projects — no disk scan. scope=all (default: sources + dependencies), project (sources only), or dependencies (JDK + libraries). Each match has "name" (FQN), "path" (absolute source file, absent for binary-only JDK/library types), and "project". Pass "path" to read_file or open_pos. "truncated": true means more than "limit" (default 50, max 200) matched — narrow with kind=exact or scope=project.
