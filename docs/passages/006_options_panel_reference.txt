Customise the plugin behavior by navigating to `Tools > Options > BeanBot`. The panel is split in two: the **Categories** tree on the left picks a page, and that page opens on the right under its own **Settings:** heading. Three categories group the pages — **Core Service** holds *Assistant*, *Chat Behavior* and *Appearance*, **System** holds *General*, *Experimental* and *Session Limits*, and **IDE Extensions** holds *Features* and *Context Actions*. Selecting a category expands it; selecting a page shows it.

Additionally, the plugin includes a background **Update Checker Service** that automatically queries for new releases (with randomised intervals between 16 and 24 hours). You can toggle the update checks under `Tools > Options > BeanBot > System > General > Check for Updates`. When an update is found, you will be prompted with a dialog to download the update immediately, get reminded later, or skip the version entirely.

A one-character marker next to an option name tells you when its value takes effect, and a legend line at the top of the panel repeats the key. **¹** means the running IDE only reads that value while it starts, so the change applies after you restart NetBeans — a bar at the top of the panel lists what is still waiting, and your sessions are restored automatically after the restart. **³** means the change applies to sessions you create from then on; sessions already open keep the value they started with. **²** means the current chat keeps the old setting until its history is reloaded. Options without a marker take effect as soon as you click **Apply** or **OK**.

This page describes every preference, grouped by the page that holds it.

An explicit choice wins over detection and survives path changes; a conflicting binary name shows a one-click switch instead of replacing your choice. Marked <em>¹</em>.</td></tr>
<tr><td><strong>Launch through WSL (Windows only)</strong></td><td>Off</td><td>When enabled, all Harness invocations (running the daemon and token-usage stats for supported agents) are wrapped through <strong>WSL</strong> using <code>wsl.exe</code>. The resolved Windows executable is automatically translated to its WSL mount path, so custom/WinGet/Choco-shim install locations resolve correctly. If the Harness is installed as a native Linux binary inside WSL (no Windows executable found), it is invoked directly on the WSL PATH. Marked <em>¹</em>.</td></tr>
<tr><td><strong>Browse...</strong></td><td>—</td><td>Opens a file chooser to select the executable.</td></tr>

##### System › General

<table class="ug-table">
<thead><tr><th>Preference</th><th>Default</th><th>Description</th></tr></thead>
<tbody>
<tr><td><strong>Check for Updates</strong></td><td>On</td><td>Enables the background <strong>Update Checker Service</strong>, which queries for new releases at randomised intervals between 16 and 24 hours. When an update is found you can download it immediately, get reminded later, or skip that version. A check can also be run on demand from the toolbar's help menu (<strong>Check for Updates</strong>).</td></tr>
<tr><td><strong>Editor Line Height Correction</strong></td><td>1.0</td><td>Multiplier applied to the editor's line height (0.5–3.0, step 0.1). Values above 1 increase the spacing between lines; the value is stored in the editor's own preferences, so it applies to every editor, not only the chat.</td></tr>
<tr><td><strong>Enable Internal MCP Server</strong></td><td>On</td><td>Offers the agent the plugin's IDE tool set (open-file context, editor search, file tools, git/hg, tasks) over an internal MCP server. Marked <em>¹</em>.</td></tr>
<tr><td><strong>Internal MCP Server Port</strong></td><td>0</td><td>Fixed port for the internal MCP server. <code>0</code> lets the IDE pick a free port, which is the recommended setting; a fixed port is only useful when something outside the IDE must reach the server. Marked <em>¹</em>.</td></tr>
<tr><td><strong>ACP file access</strong></td><td>Allow (project only)</td><td>The policy for the agent's own <code>fs/read&#95;text&#95;file</code> and <code>fs/write&#95;text&#95;file</code> calls: <strong>Allow (project only)</strong> permits reads and writes inside the session's project, <strong>Read external, write project</strong> permits reads anywhere but keeps writes inside the project, and <strong>Read-only</strong> permits project reads and rejects writes. Credential files are always refused, and writes inside <code>.git</code>, <code>.hg</code> and <code>.mvn</code> are always rejected. The policy governs the ACP file tools only — the agent's own shell access is not sandboxed.</td></tr>
<tr><td><strong>Command Whitelist</strong></td><td>(empty)</td><td>Opens a dialog with <strong>Denied</strong> and <strong>Allowed</strong> lists for the <code>run&#95;command</code> MCP tool, one executable name or glob per line (<code>*</code> and <code>?</code> supported; matching is by executable name, so <code>./mvnw</code> matches <code>mvnw</code>). Denied always wins, and a denied <code>*</code> denies everything. When either list is set, shell operators (<code>; | &amp; &gt; &lt;</code>, <code>$(…)</code>), environment assignments and command chaining are rejected, so an allowed binary cannot smuggle in another. Both lists empty leaves the command string unrestricted. The button's tooltip summarises the current lists.</td></tr>
</tbody>
</table>

##### System › Experimental

The unfinished features live on their own page rather than in the General settings.

<table class="ug-table">
<thead><tr><th>Preference</th><th>Default</th><th>Description</th></tr></thead>
<tbody>
<tr><td><strong>Enable ACP server restart on project switch (Experimental)</strong></td><td>Off</td><td>Binds the ACP server's working directory to the project of the session being opened, restarting the server when that project changes. The setting wins for every harness, including goose. Off by default while the feature stabilises. Its tooltip carries the full explanation: a project switch restarts the server and ends every session it is serving, while when disabled the server keeps the directory it was started with and only a manual restart or an IDE restart rebinds it — except that goose moves the loaded session's working directory in place, so that session opens in its own project without a restart. Marked <em>¹</em>.</td></tr>
<tr><td><strong>Auto-backup uncommitted changes on turn start (git/hg) (Experimental)</strong></td><td>On</td><td>Stashes uncommitted changes in git/hg repositories before each turn, so the AI can be rolled back safely. See [[Auto-Backup on Turn Start]].</td></tr>
</tbody>
</table>

##### System › Session Limits

<table class="ug-table">
<thead><tr><th>Preference</th><th>Default</th><th>Description</th></tr></thead>
<tbody>
<tr><td><strong>Session Idle Timeout (seconds)</strong></td><td>600</td><td>How long (0–3600, step 5) a request may sit idle — with no data arriving from the server — before it is failed. This is an <em>idle</em> timeout, not an absolute deadline, so long-running responses that keep streaming are never cut off.</td></tr>
