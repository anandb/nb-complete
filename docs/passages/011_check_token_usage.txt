Click the **Currency/Token Stats** icon on the toolbar to open the token and cost panel. It summarises every harness from data captured locally in the IDE: session, message and active-day counts, plus total cost, per-day averages, per-session token averages and median, and the summed **Input**, **Output** and **Cache Read** figures. Pick a day window and filter to the current project or all projects, then press **Refresh**. The [[Context Usage Meter]] in the assistant's bottom status row shows the current session's context fill and helps you decide when to run `/compact`.

The **Tool Calls** table counts every captured execution, one row per tool, with a bar for each tool's share of the window and a **3 failed** style note when some of its executions ended in an error. It includes calls to the plugin's own MCP tools, the harness's ACP `fs/read_text_file` and `fs/write_text_file` requests, and external MCP executions reported by goose, codex-acp, opencode and omp, listed as `server/tool`; the internal server is counted once. Calls made while no session is active are still counted.

**Reset** deletes every captured token, cost, message and tool-call record from the local database, so all figures read zero. It asks for confirmation first, because the delete is permanent: sessions, pinned messages, input history and cached model lists are kept.

**Note:** These figures are approximate. They are assembled from the usage data each harness reports, and harnesses report it differently — some include the cached read in their input count, and subscription-backed or free models often report no cost at all, so **Total Cost** understates their usage. A figure a harness reports as negative is ignored and counted as zero, so no total can go below zero. Expect minor discrepancies: treat the panel as a close estimate of your usage, not an exact bill, and do not be surprised if it differs slightly from your provider's own dashboard.
