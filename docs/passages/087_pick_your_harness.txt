BeanBot doesn't talk directly to AI services, it communicates via coding agents or harnesses, these applications interface with LLM providers like Anthropic or OpenAI, and provide authentication, persistence and context management. Most of them support a protocol called ACP or Agent Client Protocol that simplifies and standardises LLM access for IDEs and Editors, BeanBot takes advantage of this capability, we can connect to any provider or model as long as we find a suitable harness that speaks ACP.

In this guide you might also see a harness referred to as an ACP Server, an Agent Server, or simply server, in the context of this plugin it's just a conduit for communicating with a remote LLM. These are the harnesses currently supported, pick the one you want to use. Even unlisted ones might work, but you have to experiment and find out.

Some harnesses have **limited ACP support**: BeanBot can still connect and chat through them, but parts of the IDE integration are unavailable. The harness chooser (and the **Harness** dropdown under **Options > BeanBot**) labels those **Limited** — hover the badge or item to see exactly what is missing. Currently that is [[OpenClaw Agent]], [[Jcode Agent]], [[Gemini Agent]], [[PI Agent]] and [[Cline Agent]]; each page has the details. A harness's tier can change as its ACP support improves.

If you are not sure, The plugin will detect installed harnesses and let you choose at startup.
