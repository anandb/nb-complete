#### Install

- **macOS / Linux / WSL (install script)**: `curl -fsSL https://x.ai/cli/install.sh | bash`
- **Windows (PowerShell)**: `irm https://x.ai/cli/install.ps1 | iex`

CLI docs: <a href="https://x.ai/cli" target="_blank" rel="noopener">x.ai/cli</a>.

#### About

<a href="https://x.ai/cli" target="_blank" rel="noopener">Grok Build</a> is xAI's coding agent command-line tool. Running <code>grok agent stdio</code> makes it act as an **ACP server** over stdio: it speaks JSON-RPC on stdin/stdout and is meant to be spawned by an ACP-aware editor, so it is not a command to run yourself.

The executable you configure in BeanBot is <code>grok</code>, run with the default launch arguments <code>agent stdio</code>.

**Authentication** is a CLI prerequisite: run <code>grok login</code> in a terminal (or set <code>XAI&#95;API&#95;KEY</code>) before the first session. BeanBot has no in-chat sign-in, so a fresh install without credentials fails <code>session/new</code> — sign in first, then pick Grok in the chooser.

Grok in BeanBot supports:
- [[Editor Context->Automatic Context Capture]] Seamlessly injects the active editor state into agent prompts.
- **[[MCP Tools]]**: Grok accepts a per-session MCP server, so BeanBot hands it the plugin's internal server automatically — no manual registration is needed.
- **Model Selection**: Exposed as an ACP config option, so the in-session model dropdown works.
- **Agent / Mode List**: The agent selector is offered, and mode changes go through the protocol's mode request, so the dropdown works in an open session.
- **Session List**: Sessions come from Grok itself, so the dropdown reflects its own list and needs no local tracking.
- **Session reload**: Grok implements <code>session/load</code> and advertises <code>session/close</code>/<code>session/resume</code>, so [[Reloading a Session]] works for sessions it has already persisted.
- **Interjected prompts**: while Grok is working, a message you send joins the running turn through its <code>x.ai/interject</code> extension and is applied at the next safe point. BeanBot probes the extension per process; if the running build does not have it, the message waits in the [[Queuing Messages]] queue instead.
- **Token statistics**: Grok sends no standard <code>usage&#95;update</code>; it reports the turn's usage in <code>&#95;x.ai/session&#95;notification</code> frames and in the prompt result. BeanBot records that per-turn usage, so [[Check token usage]] works without double-counting.

#### Limitations

- **No session delete or fork**: Grok advertises neither <code>session/delete</code> nor <code>session/fork</code>, so the dropdown has no **Delete Session…** item and a session stays in the list after you leave it. [[Archiving Sessions]] is local only.
- **Model switching path**: BeanBot changes the model through Grok's <code>model</code> config option and mode request, not the dedicated model request. The dropdown shows the options Grok reports back, not a fixed list.
- **Interjection fallback**: the interject extension is not advertised in the handshake, so BeanBot probes it when the server starts. A build without it falls back to the normal queue; a message never gets sent as a second prompt into the running turn.
